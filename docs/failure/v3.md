# Failure stories — v4 prompt-engineering iteration

> Captures the prompt + validator work in commit `fbd60f4`, evaluated on the
> 13 cases that failed in the v3 baseline run
> (`evals/results/baseline/metrics/summary.json`, run `20260724_215741`).
> The v1 / v2 failure stories are in [`v1.md`](v1.md) and [`v2.md`](v2.md).

**Runs:**
- `agent(gpt-4o-mini) + new prompts` — `prompt_fix_gpt4o_mini_v4_20260901_220337` — **3/13 (23.08%)**
- `agent(gpt-5.4)     + new prompts` — `prompt_fix_gpt5_v2_20260828_114740`   — **5/13 (38.46%)**

The same code produces different lifts depending on base-model strength.
gpt-5.4 unlocks `h04`, `h05`, `h09` (4-hop + window-function composition)
that gpt-4o-mini can't get past. Honest prompt-only attribution, on the
smaller model, is **+23 percentage points** (0% → 23%); the additional lift
to 39% on gpt-5.4 is mostly model-driven.

## What changed

### 1. `agent/prompts/role.md` — Hard rules R9, R10, R11

**R9 No invented columns.** Every column must appear in the Semantic
Model table inventory. `products` has no `product_name` (only
`product_name_lenght`); identify products by `product_id`.

**R10 Qualify columns in multi-table joins.** When `FROM` joins 2+
tables, every column reference must be prefixed with its table alias.
`customer_id` is ambiguous between `orders` and `customers`.

**R11 Match aggregate to grain.** Per-order → `COUNT(DISTINCT order_id)`.
Per-customer → `COUNT(DISTINCT customer_unique_id)`. Per-line-item →
`COUNT(*)` on `order_items`. No defensive `LIMIT 1000` on aggregations.

### 2. `agent/prompts/semantic_model.yaml` — Category-name rule

**Removed** the 4-line `### Category Examples` synonym block that taught
the model to substitute English → Portuguese directly in `WHERE`:
```yaml
- "electronics" → informatica_acessorios   # ← actively misleading
- "furniture"   → moveis_decoracao
- "health/beauty" → beleza_saude
- "sports"      → esporte_lazer
```

**Added** a 10-line rule forcing the correct pattern:
```yaml
### Category Names (English ↔ Portuguese)
- 71 categories have English translations in product_category_translation.
- For ANY English category name, JOIN product_category_translation and
  filter on product_category_name_english = '<English>'.
- Do NOT substitute English → Portuguese directly in WHERE.
- Do NOT wrap product_category_name_english in COALESCE(...) for
  grouping or filtering.
```

### 3. `agent/prompts/few_shot.yaml` — Example 16

New 4-hop walkthrough (`orders → order_items → products →
product_category_translation`) with `order_status='delivered'`, two
`IS NOT NULL` checks, English-category filter, and `COUNT(*) AS n_orders`
audit column. Models all 4 hops in one inner subquery.

### 4. `agent/validator/sql_validator.py` — R10 column-existence

- New `SCHEMA_COLUMNS` dict (10 tables, 56 columns) mirroring
  `semantic_model.yaml`.
- New `validate_r10_column_exists()` walks the AST and rejects invented
  columns like `p.product_name`.
- Bug fix mid-run: bare-identifier references matching a SELECT alias
  are now skipped, so `ORDER BY my_alias` after `... AS my_alias` is no
  longer false-positive-blocked.

## Still failing — 7 cases

These are execution-shape disagreements between model output and gold,
not structural bugs:

- `e01` — adds 3rd `revenue` column; gold has 2
- `e13` — `COUNT(DISTINCT customer_unique_id)` vs gold's `COUNT(*)`
- `h04` — `COUNT(DISTINCT order_id)` denominator vs gold's `COUNT(*)`
- `h05` — window `PARTITION BY` shape vs nested subquery
- `m01` — extra `n_orders` audit column; `EXTRACT` vs `DATE_PART`
- `m05` — tie-breaker `n_reviews DESC` vs gold's `category`
- `m13` — spurious JOIN to `orders`; gold uses no JOIN

Fixing these at the prompt layer would require stricter "no extra
columns", strict ORDER-BY mirroring, and tighter "no defensive JOIN"
rules. Likely **+1-2 cases** at best; diminishing returns.

## Notes on the model split

- The **+39% headline is gpt-5.4-specific**. Same code on gpt-4o-mini
  shows +23% — the model upgrade does most of the heavy lifting on
  `h04`, `h05`, `h09` (4-hop + window composition cases).
- A clean attribution would require a same-model rerun on the **old**
  prompts to baseline gpt-5.4 itself; not done in this iteration.
- Cost on gpt-4o-mini: ~$0.0009/query (new) vs ~$0.0008/query (old) —
  ~$0.0001/query increase from the +845 input tokens.
